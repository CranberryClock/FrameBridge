# TCW-006 implementation plan

1. Close TCW-005 documentation without rerunning its acceptance soak.
2. Add a vendor-independent temporal contract library: validated render/output
   extents, unjittered history, deterministic jitter, reset reasons, and CPU
   motion-vector oracle. Keep all future Streamline/DLSS types out of this layer.
3. Add a replaceable `IUpscaler` seam with a deterministic native reference
   implementation and explicit output-resource ownership. Preserve the existing
   native Dawn/D3D12 presentation and loopback receiver behavior.
4. Extend native submissions with temporal metadata, reset/history handling,
   render-scale selection, and diagnostic capture metadata. Add active Release
   tests, including a negative motion-direction control.
5. Validate clean Release/TypeScript builds, native/browser integration, and a
   real 600-second render-scale-0.5 stability run. Record only safe evidence and
   stop at the TCW-006 review gate.

Decisions: render scale is a local/native setting (`--render-scale` or
`FRAMEBRIDGE_RENDER_SCALE`), never a protocol mode. Motion vectors are
previous-to-current in render-pixel units, top-left origin, camera-inclusive,
unjittered, with `mvecScale=(1,1)`. Jitter uses a finite 8-sample Halton(2,3)
sequence in render-pixel units and is disabled for ordinary presentation.

TCW-007 priority change: return the completed native reference-upscale image to
the authenticated browser mirror. TCW-006R temporal findings remain tracked
debt; this packet does not repeat the exhaustive temporal acceptance suite.
